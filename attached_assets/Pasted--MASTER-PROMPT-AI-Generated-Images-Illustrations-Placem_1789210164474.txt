## 0. WHY THIS EXISTS (read before building)

- **Phosphor Icons** (from the other master prompt) = small functional UI icons (buttons, nav, form fields). They are code, not images — nothing to generate.
- **This document** = actual pixel images (illustrations, hero graphics, background art) that need to be generated once by an image AI, saved as files, and referenced in the code like any normal image asset.

If your coding tool (Claude Code / Cursor / bolt.new / v0) has an image-generation capability built in, it can generate these directly. If not, generate each one separately using the prompts below in any image tool, then drop the file into the exact path given, and the code will pick it up.

## 2. READY-TO-USE GENERATION PROMPTS

Copy these directly into your image generator. All of them are written to produce a single consistent visual language — dark, glossy, tech-forward, gradient-lit. None reference real logos, brands, or copyrighted characters (YouTube's logo/branding must NOT be reproduced — see Section 5).

## 3. STYLE CONSISTENCY RULES (apply to every image above)

- **Color grading**: every image must lean into the same 3 tones — deep navy/charcoal (`#0B0F19`–`#12172A`), electric blue (`#2563EB`), and neon purple (`#8B5CF6`). No warm tones, no unrelated colors.
- **No text baked into images** — all copy stays as real HTML text for accessibility and easy editing.
- **No literal logos** — never generate the YouTube play-button logo or any recognizable brand mark; use abstract/generic play-shape or signal/orb motifs instead (trademark safety).
- **Consistent render style** — pick ONE style (recommended: soft 3D/glass render, like the prompts above) and keep every image in that same style. Do not mix flat illustration with photoreal render.
- **Format**: export/generate as `.webp` for smaller file size; keep a `.png` fallback only for image #4 (badge, needs transparency and webp transparency isn't universally supported by older tools).

## 4. IMPLEMENTATION INSTRUCTIONS FOR THE CODING TOOL

- Store all images under `/public/images/` using the exact filenames in the table above.
- Reference them with lazy loading:
  ```jsx
  <img src="/images/hero-visual.webp" alt="Product visual" loading="lazy" className="..." />
  ```
- **Until the real generated image exists**, render a graceful placeholder in its exact place so layout never breaks — a plain gradient `div` matching the section's color scheme, same aspect ratio as the target image:
  ```jsx
  <div className="aspect-[6/5] rounded-2xl bg-gradient-to-br from-accent-primary/20 to-accent-secondary/20" />
  ```
  Replace this div with the real `<img>` tag once the file is generated and placed — leave a `// TODO: replace placeholder with hero-visual.webp` comment at each spot.
- Background images (`hero-bg-glow`, `steps-bg-pattern`, `cta-bg`, `footer-texture`) go on the section wrapper as CSS `background-image`, not as `<img>` tags, so they sit behind text content:
  ```jsx
  <section style={{ backgroundImage: "url('/images/cta-bg.webp')" }} className="bg-cover bg-center">
  ```

---

## 5. TRADEMARK / COPYRIGHT NOTE

Because this product integrates with YouTube, it's tempting to use YouTube's red play-button logo in generated art — don't. Trademarked logos should never be reproduced in generated images. All prompts above are written to produce **generic, abstract signal/orb/play-shape motifs** instead — this keeps the visuals safe to use commercially without needing YouTube's brand permission.
